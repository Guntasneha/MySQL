TCL COMMANDS

what is Transaction
------------
the process of combining all related operation in a single unit and executing then according to the rule 'either all operations should succeed or none should succeed' is called transcation management

A transaction is considered a single unit of work and follows the principle "either all or none"

example
--------
funds transfer
consider a money transfer process b/w two accounts:
Debit amount from the sender's account
Credit amount from the receiver's account
Both operations should be executed as a single transaction
If the amount is debited from the sender's account successfully, but crediting the receiver's account fails, it may lead to data inconsistency problems.

they are two types
-------------

1. local transaction
-----------
In local transaction all operations of a transaction are executed on the same database

example:
funds transfer from one account to another account where both accounts belong to the same bank.

2.global transaction
---------------
In global transaction all operations of a transaction are executed on the different database

example:
funds transfer from one account to another account where both accounts belong to the different bank.


ACID PROPERTIES
------------

A --> ATOMICITY : all or nothing

C --> CONSISTENCY : the database remains in a valid state

I --> ISOLATION : transactions do not interface with each other

D --> DURABILITY : committed changes are permanent


TCL(TRANSACTION CONTROL LANGUAGE) COMMANDS
----------------------------------
1. COMMIT
2. ROLLBACK
3. SAVE POINT

1. commit
-----------
commit is used to permanently save all changes made during the current transaction into the database

once committed

changes becomes permanent
others users can see the changes
you cannot undo the changes using rollback

2. rollback
------------
rollback is used to undo all changes made in the current transaction before a commit

if something goes wrong. rollback restores the database to its previous state

INTRODUCTION TO STORED PROCEDURES
--------------------------

A stored procedure is a named, precompiled collection of one or more sql statements that is stored inside the database and can be executed called whenever required. instead of sending long block of sql from an application every time, the application simply calls the procedure by name.

why we stored procedures
------------
performance
reusability
security
reduced network traffic
maintainability
consistency

Advantages
-----------
faster execution after completion
reduced duplicate sql
supports transaction, loops, conditions, variables,....etc
easy maintenance

Disadvantages
-----------
debugging can be difficult
vendor specific  syntax
complex procedures may become hard to maintain

Syntax to create stored procedures
---------------------------
DELIMITER //
CREATE PROCEDURE PROCEDURE_NAME()
BEGIN
-----sql statements
END //
DELIMITER ;


IN PARAMETER
-----------
An in parameter is used to pass a value into a stored procedure. The procedure can use the value, but changes made to the parameter inside the procedure are not returned to the caller

Syntax
-------
CREATE PROCEDURE procedure_name(IN parameter_name datatype)
BEGIN
  sql statements
END ;
DELIMITER ;

OUT PARAMETER
-------------
AN out parameter is used to return a value from the stored procedure to the caller. the caller provides a variable to receive the result.

Syntax
-------
DELIMITER //
CREATE PROCEDURE procedure_name(OUT parameter_name datatype)
BEGIN
    set parameter_name=value;
END ;


DELIMITER //
CREATE PROCEDURE maximumsalary(OUT maxsal decimal)
BEGIN
    set parameter_name=value;
END ;

INOUT PARAMETER
---------------
An Inout parameter is used when we want to send a value into the procedure and receive the modified value back

Syntax
------
CREATE PROCEDURE procedure_name(INOUT parameter_name datatype)
BEGIN
    SET parameter_name=new_value'
END //
